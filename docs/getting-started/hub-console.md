# Hub 与 Console 使用指南

本页面向想运行 Robonix 的使用者：从 Hub 选择适用配置，在目标机器的 Console 中安装、配置和启动，再用 Client 完成第一条任务。没有实体机器人时，可以走 TIAGo Webots 仿真路线。

| 工具 | 用来做什么 | 在哪里使用 |
|---|---|---|
| [Hub](https://hub.robonix.ai/discover) | 查找整机配置与软件包，保存和分享配置备份 | 云端网站 |
| Console | 安装配置、构建软件包、启动停止、查看日志 | 安装在机器人主机或仿真电脑上，用浏览器打开 |
| [Client](client.md) | 与机器人对话、下达任务、查看执行过程 | 操作者电脑，可与 Console 共用一台 |

Console 右侧的 AI 配置助手用于管理配置；机器人拍照、移动等任务通过 Client 下达。

:::note[适用范围]
操作流程以 Console `0.1.0-beta.22` 为依据，截图中的旧名称在图注中说明。升级后以实际界面和整机条目的 README 为准。原书命令行教程有独立的源码版本与验收范围，不能将它们当成所有 Hub 配置的兼容保证。
:::

## 选择使用路线

| 你的情况 | 从哪里开始 | 开始前确认 |
|---|---|---|
| 没有实体机器人 | [TIAGo Webots 配置](https://hub.robonix.ai/package/robonix.robot.pal_robotics.tiago_webots)，再按本页安装流程操作 | 配置 README 所需的系统、图形环境、Docker 和设备权限 |
| 已有实体机器人，目录中有适用配置 | [Hub 机器人目录](https://hub.robonix.ai/discover/robot)，再按本页安装流程操作 | 型号、传感器、计算平台、驱动与依赖相符 |
| 已有部署仓库 | 按仓库 README 准备目录，再[登记已有部署](#新建登记与切换部署) | 目录包含可用的部署清单及所需资源 |
| 没有适用的整机配置 | [机器人接入指南](../integration-guide/vendor-onboarding.md) | 需要先适配本体，不能仅安装同名软件包就运行 |
| 要固定源码、调试构建或接入仿真本体 | [Webots 命令行教程](quickstart.md)或 [MuJoCo 本体接入](../integration-guide/mujoco-simulation-onboarding.md) | 按对应教程的版本和前提操作 |

TIAGo 的原 Webots 教程验收环境为 Ubuntu 22.04 或 Debian 13、`x86_64`、NVIDIA 图形环境和 Docker。Hub 条目的要求可能不同，安装前先核对 README；具体主机检查见[命令行教程](quickstart.md)。

以下主流程的完成标志是：Console 显示“运行中”，Client 连接在线，并收到与现场或仿真画面相符的任务结果。

## 安装 Console 并登录

### 准备账户

已有可用的 Hub 账户可直接继续。收到邀请邮件时，在 72 小时内打开链接并输入验证码，按页面要求阅读个人信息告知和许可协议、完成确认，再设置密码。在 [Hub](https://hub.robonix.ai/discover)确认账户可登录；开启二次验证时还需验证码。

Console 提示未同意许可协议时，先到 Hub 完成确认，再重新登录。

### 在目标机器安装

安装器支持 `x86_64` 和 `aarch64`，包括 Jetson。在**运行 Robonix 的机器人主机或仿真电脑上**，以普通用户执行：

```bash
curl -fsSL https://hub.robonix.ai/install | bash
```

不要用 root 或在命令前加 `sudo`；安装器补充系统软件包时会按需询问权限。它会检查主机、校验发布文件、显示许可协议、安装 Console，并设置当前用户的自动启动服务。已有 Robonix 时直接使用，没有时下载源码并构建。

安装完成应显示 Console 的访问地址，并确认页面已响应。驱动、仿真环境和其他整机依赖仍需按条目 README 准备。

<details>
<summary>安装位置与过程截图</summary>

Console 程序位于 `~/.local/bin/robonix-hub`；部署、历史和日志位于 `~/.local/share/robonix-hub`。首次安装 Robonix 时使用 `~/.local/share/robonix-hub/robonix`。

![Console 安装器显示主机检查、下载和服务配置进度](/img/hub/console-install-progress.png)

遇到错误时先保留当前步骤和终端报错，不要将下载完成当成安装成功。

</details>

### 设置模型服务

安装时按提示填写以下三项；也可跳过，稍后在“设置 → 机器人环境变量”补齐。

| 页面字段 | 变量 | 要填写的内容 |
|---|---|---|
| VLM 终端 URL | `VLM_BASE_URL` | 兼容 Chat Completions 的接口地址 |
| VLM KEY | `VLM_API_KEY` | 服务访问密钥 |
| VLM 模型 | `VLM_MODEL` | 模型名称 |

Pilot 和配置助手使用这组设置。配置助手需要模型支持工具调用；后面的相机任务还要求图像理解能力。这些本机变量不随部署上传。安装器检测到已有值时会询问是否保留，密钥只显示末四位。

### 打开管理页面

在目标机器的浏览器打开 [http://127.0.0.1:4880](http://127.0.0.1:4880)，用 Hub 账户登录。默认只允许本机访问。

从另一台电脑管理时，在**操作者电脑**建立 SSH 隧道。把 `ROBOT_USER`、`ROBOT_HOST` 替换为目标机器的用户名与地址：

```bash
ssh -N -L 4880:127.0.0.1:4880 ROBOT_USER@ROBOT_HOST
```

保持终端打开，再在操作者电脑浏览器访问上述本地地址。看到“概览”和“配置”后继续。

**这条隧道只转发 Console 管理页面。** Client 还需连接 Atlas 以及它发现的组件，见[连接 Client](#连接-client-并完成第一条任务)。

## 选择并安装整机配置

整机配置将部署清单、软件包、参数和附带文件组织在一起。在 [Hub 机器人目录](https://hub.robonix.ai/discover/robot)搜索型号，查看说明、版本、使用的软件包和仓库 README，确认真机或仿真环境、传感器与计算平台相符。TIAGo Webots 是仿真配置，同名真机需要自己的适配。

1. 在目标机器的 Console 打开“目录 → 机器人”，找到同一条目；仿真路线搜索 `tiago_webots`。
2. 点“安装到这台机器人”，核对确认框中的配置和目录，再确认。
3. 等下载完成，进入“配置”，确认生成了第一个配置版本。

![Console 中确认将要安装的整机清单、软件包与附带文件](/img/hub/console-install-confirm.png)

*确认安装对象和下载内容。截图与实际界面的按钮名称可能不同。*

整机自带的本机软件包、配置文件和仿真脚本会一起下载；远程软件包随后在“更新”页下载、构建。**当前部署为空时安装到其中；已有配置时新建部署并切换过去**，原部署保留。

Hub 网站用于查找和阅读，安装操作在目标机器的 Console 中完成。找不到适用条目时，按[使用路线](#选择使用路线)选择登记已有目录或开发适配。

## 检查配置并保存

### 核对当前部署和参数

先在“概览”核对当前部署名称；后续配置、历史和启动操作都作用于它。

“配置”按系统服务、自带服务、原语包、服务包、技能包、环境变量和发布信息分组。Atlas、Executor、Soma 是必需系统组件，不能关闭。首次使用保留整机配置的组合，停用软件包前先核对依赖。

展开条目，点击参数行修改；未设置项显示默认值，“改回默认”清除自定义值。相机、雷达等提供方应指向实际条目；提供方在另一台机器时使用“手动填写”。没有分组表单的包按键值编辑，说明以软件包 README 为准。

![Console 配置页中的系统服务、软件包与参数分组](/img/hub/console-configuration.png)

*按整机 README 核对设备、路径与提供方，不要照抄另一台机器的参数。*

### 补齐变量与软件包

“概览”或“配置”提示缺少必填变量时，点“设置”补齐：

| 位置 | 作用域 | 是否随部署上传 |
|---|---|---|
| 设置 → 机器人环境变量 | 本机各部署共用 | 不上传 |
| 配置 → 环境变量 | 当前部署 | 属于部署清单；上传前检查密钥替换提示 |

两处同名时以部署变量为准。模型密钥等本机共用值优先放在机器人环境变量中。

需要增加功能时，在相应分组点“添加软件包”，搜索后先看 Hub 详情中的用途与依赖，再添加并检查参数和提供方。原语包提供硬件能力，服务包提供建图、导航等功能，技能包组合能力完成任务；包名本身不代表整条任务链已可用。

<details>
<summary>添加本机软件包或直接编辑清单</summary>

选择“本机目录”后，从部署目录内含 `package_manifest.yaml` 的子目录中选择软件包。没有整机配置时，可先在“设置”新建空白部署，逐项添加，再保存首个版本。

需要直接修改清单时，点“编辑 YAML”，修改后“返回表单”。字段和运行关系见[部署与启动](../architecture/deployment-and-startup.md)。

</details>

### 保存新版本

点“保存为新版本”，填写修改说明，检查差异并保存，再到“历史”确认新记录。新增或更换软件包后先构建；启动时读取的配置需要重新启动 Robonix 才生效。

![保存配置时核对版本号、修改说明和高亮差异](/img/hub/console-save-version.png)

*保存前确认差异只包含预期修改。撤销方法见[恢复配置](#对比与恢复配置)。*

## 构建并启动 Robonix

### 构建软件包

在“更新”点“更新全部软件包”，等待下载和逐包构建结束。随整机安装的包显示“本地目录”，远程包下载前显示“未下载”。查看上方任务日志，确认构建成功后再继续；失败时先检查具体软件包与报错，只有确认缓存损坏时才清理缓存重建。

### 准备仿真或真机

**TIAGo Webots 路线：** 在“设置”找到当前部署路径。把 `DEPLOYMENT_DIR` 替换为该目录的绝对路径，在**仿真电脑终端**执行：

```bash
cd "DEPLOYMENT_DIR"
bash sim/start.sh
```

保留终端，等待 Webots 窗口和传感器就绪，再启动 Robonix。此脚本属于相应整机配置，其他仿真按自己的 README 操作；图形、容器或设备问题见 [Webots 教程](quickstart.md)。

**实体机器人路线：** 按整机 README 准备驱动、设备权限与环境脚本，完成[本体接入指南](../integration-guide/vendor-onboarding.md)要求的停止行为、限速与急停检查，清空测试区域，再继续。

### 启动并检查状态

在“概览”核对当前部署，点“启动”。正常状态依次变为“启动中”“运行中”，按钮变为“停止”；失败时查看页面给出的原因和本次运行日志。

![Console 概览中的运行状态、停止按钮和 Client 连接信息](/img/hub/console-running.png)

*确认“运行中”，连接 Client 时复制自己机器显示的地址与 Atlas 端口。*

同一台机器一次只能运行一套部署。切换部署不会自动停止原运行；另一套正在运行时，先点“停止它”，再启动当前部署。“开机自启”也只能设置一套。

### 查看日志与停止

| 要检查的内容 | 查看位置 |
|---|---|
| 下载、构建与更新失败 | “更新”的任务日志 |
| 启动过程 | “日志”中本次运行的“rbnx 输出” |
| 某项功能异常 | 同次运行中对应组件或软件包的日志标签 |

运行日志按启动记录保存，默认保留最近十次；可筛选关键词、跟随最新输出或下载完整日志。

结束时先在 Client 取消任务，再到 Console“概览”点“停止”；仿真进程按整机说明另行结束。真机出现危险时使用物理急停，不能等待网页取消替代急停。

## 连接 Client 并完成第一条任务

### 安装与连接

在**操作者电脑**按原书 [Client 使用指南](client.md)安装 Client，那里保留 Linux、macOS、Windows、音频与健康状态的完整说明。

1. 在 Console“概览 → 连接 robonix-client”复制机器人地址和 Atlas 端口。
2. 按 Client 指南启动，打开 [http://127.0.0.1:7860](http://127.0.0.1:7860)。
3. 填写 **Robot Host** 和 **Atlas Port**，点 **Connect**，等待在线。**Liaison Endpoint** 通常留空，由 Client 自动发现。

同机连接可使用 `127.0.0.1`。跨电脑连接时，若 Console 提示组件只监听本机，点“允许其他机器连接”并确认：Console 会修改监听地址、保存为新版本，**重新启动 Robonix 后生效**。仅在可信局域网或 Tailscale 网络中开放，不要直接暴露到公网。

Client 通过 Atlas 发现组件后还要直接连接它们，不能只转发 Atlas 或 Console 端口。需要手动配置时，按 [Client 的机器人端准备](client.md)核对端点可达性。

![Client 中填写机器人地址和 Atlas 端口并确认在线](/img/hub/client-connected.png)

*使用 Console 的实际值，截图地址仅用于展示操作位置。*

### 发送相机任务并检查结果

先发送“目前有哪些能力？”。收到回复后，确认机器人具备可用相机和图像理解能力，再发送：

> 用头部相机拍一张前方的照片，告诉我看到了什么

这条示例适用于相应 TIAGo 配置；其他机器人应使用实际安装的相机。

![Client 中提交相机任务并查看最终回复](/img/hub/client-camera-task.png)

*等待最终回复，再对照现场或仿真画面检查描述。*

“已提交”只表示接收了任务。查看 **Current Goal**、执行状态与最终回复；已结束的过程在 **Execution history** 中回看。结果应与实际画面相符，不能仅凭回复存在就判定成功。

执行中再发送要求会调整当前任务。要取消时，点 **ABORT ALL TASKS**，等待 **Aborting** 结束并回到空闲。需要停止整套系统时，再到 Console 停止 Robonix。

需要语音交互时，按 [Client 指南](client.md)配置音频桥、麦克风与扬声器，先完成设备测试，再发语音任务。

## 运行之后做什么

这些功能依赖整机实际配置，按原书对应指南操作：

| 目标 | 入口 | 前提与结果检查 |
|---|---|---|
| 创建并保存地图 | [建图与定位](../components/mapping.md) | 雷达或 RGB-D、里程计与建图服务可用；保存后重新加载并检查定位 |
| 在地图上导航 | [导航指南](../components/navigation.md)、[Webots 示例](quickstart.md) | 已加载地图、定位正确、导航与目标输入链路就绪；检查路径、到达状态与现场 |
| 标注房间、查看相机与场景 | [场景服务](../components/scene.md) | 已保存地图与场景服务可用；图像和对象还需对应感知能力 |
| 开发自己的功能 | [开发者指南](../developer-guide.md) | 按原语、服务或技能的接口与打包要求开发、验证 |

加载地图会替换当前建图会话，先保存要保留的结果；新建地图使用新的地图 ID。RViz2 的目标按钮需要对应转发程序，不能因看到按钮就判断目标已接入。真机运动前仍需检查定位、限速、通道和急停。

## 管理部署、历史与云端备份

### 新建、登记与切换部署

一套部署是包含清单、软件包、配置和资源的目录，各有独立配置历史。首次安装会创建 `~/.local/share/robonix-hub/deployments/default`，名称为 `Default deployment`。

在“设置 → 部署”可以新建空白部署；已有仓库时，同时填写其目录路径。切换后先核对名称和参数，再按[运行流程](#构建并启动-robonix)启动。

删除前确认目录来源：**Console 创建的目录会连同文件一起删除；登记的已有目录只从列表移除，文件保留。** 最后一个部署不能删除。需要保留的本机资源先单独备份。

### 对比与恢复配置

在“历史”确认当前版本，选择旧版本，点“与当前对比”。需要恢复时先看差异，再点“回滚到此版本”并确认；回到“配置”检查，重新启动后生效。

回滚不新增版本，只恢复部署清单，**不会还原软件包代码、地图或其他资源**。直接修改过清单文件时，Console 会在下一次保存或回滚前记录这些改动。

“导出历史”可备份当前部署的全部配置版本；“导入历史”会替换当前部署已有的历史，操作前先导出留底。

### 上传与恢复云端备份

云端副本包含清单和最多最新 200 个配置版本，**不包含本机软件包、地图、模型等文件**。

在“概览 → 云端备份”点“上传此部署”，检查确认框中的主机、硬件、系统、版本数量和密钥占位符，再上传。在 [Hub 我的机器人](https://hub.robonix.ai/robots)确认副本存在；再次上传会替换同一部署的上一份副本。

在另一台机器安装 Console、登录同一账户，点“从云端下载”，选择机器人和部署。**默认下载到新部署，当前部署不变，下载后再选择切换。** 显式勾选“改为覆盖当前部署”会替换当前部署的清单与全部历史，先备份再确认。

恢复后需重新核对设备、路径与本机变量，补齐软件包和资源，再构建启动。下载配置完成不表示目标机器已可运行。

### 分享配置

在“我的机器人”中为已上传副本点“分享”，检查密钥替换方式，再生成链接。分享副本中的密钥改为环境变量引用，自己的记录不受影响；在个人主页“分享的部署”点“停止分享”可使链接失效。

接收者可免登录查看分享页。要安装，在自己的 Console 云端备份卡片中点“导入分享链接”，粘贴、打开并确认安装。空部署直接使用，已有配置时新建部署。**分享只有清单，不携带原作者的本机软件包与资源。**

分享页不进入目录搜索。发布目录条目的要求见[软件包目录与发布](../integration-guide/package-catalog.md)。空间用量与额度在 [Hub 用量](https://hub.robonix.ai/usage)查看。

## 使用配置助手与维护程序

### 用 AI 助手检查或修改配置

完成[模型设置](#安装-console-并登录)后，在 Console 右侧打开配置助手。可先输入“检查当前配置有没有问题”；已有探索技能时，也可要求“把探索的超时改成 240 秒”。

助手展示修改确认卡片时，核对对象和前后差异；点“同意”后才执行，点“拒绝”则放弃。修改配置、增删启用项、回滚、启动停止或上传云端等改变状态的操作都需确认。配置修改会保存为说明带 `(AI)` 的新版本，可在历史中恢复。

![配置助手检查配置并展示修改确认卡片](/img/hub/console-assistant.png)

*检查对象和差异后再同意，不把助手回答当成操作已成功。*

本机环境变量在确认卡片的专用输入中填写，模型看不到这个值；保存后按需构建、重启。删除部署目录、导入覆盖历史和账户操作不向助手开放，需要在相应页面手动处理。

### 分别更新 Console、Robonix 与软件包

| 对象 | 操作与影响 |
|---|---|
| Console | 在“更新”检查新版本，或使用自动更新；会重启管理程序，保留部署、历史与日志，不影响正在运行的 Robonix。新版本无法启动时回退旧版 |
| Robonix | 选择发布版本或提交 ID 后升级；会停止 Robonix、切换源码、编译安装并重建软件包。失败时退回原版本，结束后检查结果再启动 |
| 软件包 | “更新全部软件包”下载并构建；完成后核对功能与依赖，重新启动检查 |

升级前保留可用配置和必要资源。配置历史无法替代源码与数据备份。后台升级不会因关闭网页而中断；新许可协议需手动阅读并接受。

环境脚本、日志保留次数、下载镜像和机器人环境变量在“设置”管理。开启局域网访问时，同时检查允许登录的账户列表；列表留空表示不限制登录邮箱。

<details>
<summary>重新安装与卸载</summary>

再次执行[安装命令](#安装-console-并登录)可以重新安装，保留部署与历史。需要卸载 Console 时，在安装它的普通用户账户下执行：

```bash
curl -fsSL https://hub.robonix.ai/install | bash -s -- --uninstall
```

卸载停止并移除管理程序服务，保留部署、历史和日志，不等于删除机器人配置。

</details>

## 排查问题与提交反馈

| 现象 | 首先检查 |
|---|---|
| Console 打不开 | 安装终端的最终结果、服务访问地址；远程管理时 SSH 隧道是否仍连接，本地 `4880` 是否冲突 |
| 无法登录 | Hub 账户是否激活、协议确认和二次验证是否完成；Console 的账户访问限制 |
| 构建失败 | “更新”任务日志中第一个失败的软件包、依赖与网络错误 |
| 启动失败 | 当前部署、必填变量、设备权限、驱动和环境脚本；同次运行的 rbnx 输出 |
| Client 离线 | Robonix 是否运行，地址与 Atlas 端口是否正确；发现的组件是否也可达，修改监听地址后是否重启 |
| 文本正常但语音失败 | Client 音频设备测试、音频桥、Speech 与 Liaison 日志，见 [Client 指南](client.md) |
| 相机没有图像或任务失败 | 实际相机、感知服务、模型的图像支持与对应组件日志 |
| 恢复配置后不能运行 | 云端未包含的本机包、资源、设备路径与本机环境变量是否补齐 |

恢复到可用配置前先导出历史留底。代码更新引起的问题还需核对软件版本，不能仅靠清单回滚判断已恢复。

要反馈时，打开 Console 或 Hub 的反馈入口，写清型号、配置版本、时间、复现步骤、期望与实际结果和完整报错。发送前点“查看”检查附件；当前部署清单默认不勾选，按需附上并确认密钥替换。取消勾选的项不会发送，不要在描述或日志里粘贴密钥。

Console 无法连接 Hub 时可下载反馈包另行交给维护者。网站不可用时先查看 [Hub 服务状态](https://hub.robonix.ai/status)，版本变化查看[更新日志](https://hub.robonix.ai/changelog)。
