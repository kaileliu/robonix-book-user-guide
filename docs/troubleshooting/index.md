# 问题排查

从最后一个正常的步骤往下查。先保留错误和日志，再决定改配置、换版本或重装。

## 按现象定位

| 现象 | 先检查与操作 |
|---|---|
| 账户无法使用 | 完成邀请激活与协议确认；开启二次验证时输入验证码，见[安装与登录](../hub/install.md) |
| Console 打不开 | 安装是否完成、本机地址是否正确；远程使用先建 [SSH 转发](../hub/install.md#打开-console) |
| 找不到机器人或功能 | 到 [Hub 目录](https://hub.robonix.ai/discover)搜索型号或描述，见[选择配置](../hub/catalog.md) |
| 安装后启动失败 | 缺少变量、未构建、整机依赖；查看[启动日志](../hub/run.md#查看日志) |
| 模型不可用 | 服务地址、密钥、模型名和网络，见[模型设置](../hub/install.md#设置模型服务) |
| 修改没有生效 | 是否保存、部署是否正确、是否构建并重启，见[配置指南](../hub/configure.md) |
| Client 离线或音频失败 | 机器人地址、端点、音频路由，见 [Client 排错](../getting-started/client.md#排错) |
| 地图不显示或位置错位 | 传感器、地图 ID、运行模式和初始位置，见[地图教程](../tasks/mapping.md) |
| 导航不动或中途停止 | 定位、导航日志、障碍和运动保护，见[导航教程](../tasks/navigation.md) |
| 图像或物体不刷新 | 相机与感知服务，见[场景教程](../tasks/scene.md) |
| 云端恢复后不能运行 | 本地包、驱动和资源是否补齐，见[恢复配置](../hub/cloud.md#在另一台机器恢复) |

危险时先使用急停。任务已提交但没完成时，查看 Client 的当前目标、执行记录，再对照机器人日志。

## 恢复可用配置

在“历史”导出留底，选择最近可用的版本，对比、回滚并重启。配置历史不包含全部代码和资源；更新代码后出的问题，还需核对软件版本。具体步骤见[配置恢复](../hub/history.md)。

## 提交反馈

1. 点 Console 或 Hub 侧栏底部的反馈按钮；手机在右上角。
2. 选择反馈对象，写清现象、期望结果、出问题前的操作和完整报错。
3. 点“查看”检查随附内容。保留相关日志；当前部署清单默认不勾选，按需附上。
4. 确认发送，等待发送成功提示。一条反馈只描述一个问题，并注明型号、配置版本和发生时间。

![反馈窗口中的反馈对象、描述、附件预览和发送按钮](/img/hub/console-feedback.png)

*选反馈对象（1），写明问题（2）；点“查看”（3）检查附件，按需勾选清单（4），再发送（5）。*

在 Console 提交时，随附系统与硬件、版本、最近日志和管理程序设置；点“查看”可检查原文，取消勾选的项不会发送。当前部署清单默认不勾选，选中后其中的密钥会替换为占位符。在 Hub 网站提交时，随附浏览器信息。
