# 管理多套部署

一套部署是一个目录，包含部署清单、本机软件包、配置文件和仿真脚本等。每套部署有独立的配置历史，可分别保留仿真、真机或实验配置。

典型目录包括 `robonix_manifest.yaml`、`primitives/`、`services/`、`scripts/`、`config/` 和 `sim/`。新安装的 Console 会创建 `~/.local/share/robonix-hub/deployments/default`，名称为 `Default deployment`；之后的目录也会显示在“设置 → 部署目录”中。

## 确认当前部署

“设置”的部署列表显示名称和目录路径。“概览”的启动、停止，“配置”的修改以及“历史”的回滚，都作用于当前部署；操作前先核对名称。

## 新建空白部署

在“设置”新建部署，只填写名称，Console 会创建一个空目录。在该部署的“配置”页[逐项添加软件包](configure.md#添加软件包)，再保存第一个版本。

从 [Hub 目录](https://hub.robonix.ai/discover/robot)安装整机配置时，当前部署为空就安装到其中；已有配置时自动新建并切换过去，原部署保留。

从云端下载部署或导入分享链接时也遵循同样的规则：空部署直接使用，已有内容则创建新部署。一个机器人可以有多套部署，但同一时间只有一套 Robonix 能运行；“概览”的启动、停止和“配置”的修改都作用于当前部署。

## 登记已有目录

已经按仓库 README 准备好部署时，新建部署时同时填写该目录的路径。Console 会直接使用它，之后在“配置”中检查清单。

## 切换部署

在“概览”上方的选择框切换，也可从“设置”的部署列表操作。切换后先核对名称和配置，再启动。

切换当前部署并不意味着原运行自动停止。若另一套正在运行，“概览”会显示其名称并禁止再次启动；按[启动说明](run.md#启动-robonix)先停止它。

## 重命名或删除部署

在“设置”的部署列表中操作。删除前确认目录来源：

- **Console 创建的目录**：目录和其中的文件一起删除。
- **你登记的已有目录**：只从列表移除，文件保留。

最后一个部署不能删除。要保留数据，先备份配置和目录中的资源；[云端副本](cloud.md)不包含本机软件包、地图等文件。
